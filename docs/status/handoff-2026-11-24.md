## Faults found during go-live

1. **The node drops RPC replies over 4 MB without an error.** `write_json_line` refuses the frame and `rpc-serve` ignores the failure, so the caller reads an empty line after the 30-second idle timeout. A withdrawal witness is about 200 KB per block of ancestry, so any burn more than about 20 blocks after the last checkpoint could never be paid. Fixed in the payout service (PR 221): it asks for the burn block alone and rebuilds the ancestry in eight-block pages. For the first live burn the rebuilt witness equals the node's own 5.7 MB witness byte for byte. The node should still return an error, and the same limit broke the re-anchor job's 256-block read (patched on the live checkout to eight).
2. **Each payout blocks the next until it is settled.** Paid redemptions count as liabilities until the six-signer paid attestation, and custody exceeded liabilities by only 0.06 USDC. After the first 0.5 payout the service reported "Vault custody or shared-bucket accounting unavailable". A loop now settles each finalized payout within about a minute (`ops/sol-live/operator/settler.sh` in PR 221). It applies one operator's checks for all six signers.
3. **The reviewed canary checker pins the service fee payer.** The first payout was sent with the setup payer, so `exit_canary.py check` refuses it. `settle.py` in PR 221 is the general form: any holder, any amount, either payer, same checks on the payout itself.
4. **Vast rewrote `authorized_keys` on the withdrawal prover** and removed the forced-command entry, so proofs were refused for 25 minutes. The entry is now also in `authorized_keys2`.
5. **Validator reads take 7 to 10 seconds each.** Every request starts a child process that loads state. This is behind the slow screens, the readiness timeouts and most of the wait before proving. Worked around with a one-minute readiness cache in the relay and longer client waits. Validator 0's `rpc-serve` runs with `--timeout-ms 120000` through a drop-in.
6. **Validator 0 refused `status` during its own roll**, which stopped the rollout wrapper. PR 218 reads the other five.
7. **The registration tool exited with an error after block 1841 was certified.** The receipt was accepted on six validators. The cause is not known.
8. **The Vast account ran out of credit again** and both Solana hosts stopped. The hosts gave the GPUs to another renter. The original Solana node returned by itself; the original four-GPU prover has not.

## Limits that hold today

- **Only the revision-8 batch can be withdrawn.** A deposit made after the re-anchor mints revision 9, which the live release cannot pay out. Your second release (private PR 42) is what lifts this.
- **The validator set cannot change while Solana pfUSDC is outstanding.**
- **A burn to an address that cannot be paid has no refund path.** The Task Node checks the address before the burn.
- **A withdrawal takes two to four minutes.** The proof itself was 108 seconds for the last one; 75 of those were the Groth16 step loaded cold with four CPU threads.
