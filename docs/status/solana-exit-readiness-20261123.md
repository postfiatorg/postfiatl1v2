## Where the user path breaks

1. **Burn.** The holder would sign one `vault_bridge_burn_to_redeem` with owner, issuer, family, source bucket, 20,000 atoms, finalized reserve epoch and packet hash, and `solana-spl:<32-byte genesis hex>:<32-byte wallet owner hex>`. Acceptance should debit that series, reduce bucket outstanding, increase its redemption queue and record the redemption, withdrawal packet and accepted receipt. The finalized bridge-exit leaf commits the burn, bucket, amount, destination and packet. In the deployed build, the packet constructor parses an EVM source domain and destination. It cannot construct this packet. The archived Solana encoder is in `archive/20261121/private/sol/withdraw`. Compare `crates/types/src/account_owned_asset_types.rs:3099`, `crates/types/src/market_nav_asset_types.rs:1640` and `crates/execution/src/nav_vault_asset_execution.rs:7160`.
2. **Descriptor.** The family selector skips Solana ingress profiles and picks one eligible profile by epoch and activation height. The bootstrap expects chain tag `SOLANA01` and the 20-byte aliases of the Solana vault and mint. Promoting a competing descriptor through the current selector would displace the Ethereum setting used by the live service. Coexistence requires independent selection and a governed binding for the Solana bucket. See `crates/types/src/shielded_bridge_governance.rs:1561`, `crates/node/src/market_bridge.rs:1167` and `ops/sol-live/mainnet_egress.py:15`.
3. **Proof.** The payout worker needs the accepted receipt and withdrawal packet, exit-leaf inclusion proof, signed finality ancestry from a trusted checkpoint and the matching exit descriptor. The existing egress path runs the frozen SP1 Groth16 withdrawal/checkpoint guest via the Ethereum worker's Vast SSH proof host. The Solana prover tunnel serves ingress. The local frozen ELF matched SHA-256 `4d5f84493c9b02b0d2a082c446229e30ce6645210a00c271dfb125b2761c67e0`. The verifier pins program vkey `0x0015b046ba4b80c0ca7e2d9429a1f5fd88bc6d1d328cca6acec29ffdf48a9d87`. No GPU job was run. See `ops/withdraw/proof_host.rs`, `ops/withdraw/service.py:79` and `ops/sol-live/prover-start.sh`.
4. **Payout.** Finalized mainnet `getMultipleAccounts` at slot **472742804** returned executable verifier `8Dxp8bfgEh6ankapfBdkTds5cebqrtPdFxpZSP6JsGAF` and vault `GFkpeTibgdRAAAndgUMYsJnSTck91tUbrpuWBWan6z1G`. Custody `AhmUaCijypvcbYMDxeXVbUPqjPX1tiHfLH6NWkYnQTCi` held **7.657035 USDC** under vault config `JByQZxACTnFXQDGLBUKAfTysSuqtpoLHoAWqUh4ri6WG`. The verifier's light PDA `FQe34dCQg9m6yEW6NjbjoR8LfWwKGLX2hBvTdY2Lu6s1` returned null. Tag 3 requires the verifier program address's signature plus a payer to initialize the route and trusted checkpoint/committee. This is a privileged bootstrap, distinct from a loader upgrade. For an ordinary exit, a relayer pays SOL fees and rent, ensures the recipient has the canonical USDC ATA, uploads public values with tag 5, advances checkpoints with tag 8 if needed, and submits the 356-byte proof with tag 2. The unpaused verifier checks the proof and full destination, records a one-use burn marker and invokes vault tag 2. The vault signs the SPL `transfer_checked` from custody to the ATA. Tag 6 reclaims buffer rent. The recipient supplies no Solana signature. See `solana/pfusdc-egress-verifier/src/{lib.rs,vault.rs}`.
