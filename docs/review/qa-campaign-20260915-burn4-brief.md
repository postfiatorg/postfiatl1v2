# QA campaign burn 4 brief — 2026-09-15

Fourth reset-burning QA campaign, following the completed [burn 1 and burn 2](qa-campaign-20260910.md) and [burn 3](qa-campaign-20260911.md). Same operator ask: heavy adversarial code review of shipped code, one surface at a time, each seen cold. Burn 4 covers the code no earlier burn reviewed. Commit and push after every completed unit; never accumulate unpushed work.

## Boundaries (absolute)

- No Task Node action of any kind.
- No fleet mutation: no deploy, restart, configuration change, or write to any validator/RPC host or live chain. Read-only ledger/status endpoints only, and only if a unit needs them.
- No pushes to any destination other than this repository's origin main.
- No spends, rentals, external service signups, or system-level toolchain installs. Network use: git, documented read-only endpoints, and OpenRouter for Text Improvement Harness scoring only.
- Frozen artifacts stay frozen: the V1 attack-simulation outputs, the V2 gate outputs, all deployment evidence directories, benchmarks receipts, docs/whitepaper.md, docs/whitepaper_legacy.md, and the locked amendment and lock records. No whitepaper work in this burn.
- Out of scope, do not review or edit: crates/privacy_orchard, crates/privacy, crates/bridge, crates/ethereum-contracts, crates/pfusdc_proofs, crates/pftl_uniswap_proofs, crates/proofs, programs/, crates/node/src/vault_bridge_workflows.rs and any pfUSDC- or Arc-specific code inside crates/node. Another lane is reworking the bridge and Orchard code off this repository. If a finding elsewhere depends on that code, record it with the dependency named and do not fix it.
- Already reviewed, do not re-review: crates/storage, crates/execution, crates/consensus_cobalt and its oracles, crates/network, crates/mempool_dag (burn 3); wallet-extension, crates/rpc_sdk, python/ (burns 1 and 3). A burn 4 repair may touch them only when it is the minimal fix for a burn 4 finding.
- A repair that changes a consensus rule, a state-transition result, an on-disk storage format, or the bytes any validator signs or hashes is consensus-affecting: it is allowed with a regression test, but the log and the inventory row must say so, and it must not be activated, deployed, or presented as live behaviour.
- Before every commit: the strict docs build (.venv-docs/bin/mkdocs build --strict), scripts/public-doc-links, and scripts/public-secret-scan must all pass. Plain single-sentence commit messages. Findings and fixes are separate commits.
- Word findings and repairs neutrally: input validation, fail-closed handling, bounded resources, interlocks.
- When uncertain whether an action crosses a boundary: skip it and log the skip.

## A. Review surfaces, priority order

Per surface: an adversarial fresh-eyes review, a findings document docs/review/<surface>-review-20260915.md with severity, file and line, and a concrete failure scenario per finding; then fix that surface's P1 and P2 findings with minimal changes and regression tests (P3 findings are recorded, not fixed); run cargo check and the focused tests of every touched crate or module; commit findings and fixes separately. The full Rust suite is the CI verdict; the log says "full Rust suite verdict pending" for each repair until rust-ci is green on it.

1. Block finality, consensus artifacts, and signing (docs/review/finality-consensus-review-20260915.md): crates/node/src/block_finality.rs, crates/node/src/consensus_artifacts.rs, crates/ordering_fast (lib.rs and consensus_v2.rs, including the signing and verification paths burn 3 excluded), crates/crypto_provider. Focus: a vote or certificate counted twice or from a non-member, signatures verified over the wrong bytes or without domain separation, equivocation and replay of votes and certificates, view and round monotonicity, decision determinism across nodes, artifact persistence and reload after a crash.
2. Canonical types and state commitment (docs/review/types-state-commitment-review-20260915.md): crates/types (consensus_v2_types.rs, core_chain.rs, ledger_assets.rs, genesis_registry.rs, fastswap_types.rs, account_owned_asset_types.rs, market_nav_asset_types.rs, fx_fix_types.rs, nav_reserve_public_values.rs, shielded_bridge_governance.rs, fastpay_recovery_types.rs; the pfUSDC and Ethereum bridge type files are read-only context) and crates/node/src/state_commitment.rs. Focus: serialization round trips and malleability (two encodings of one value, one encoding of two values), hashing domain separation and length prefixing, integer overflow and underflow in amounts and sequence numbers, ordering of maps and sets inside hashed structures, versioning and unknown-field handling.
3. Node startup, release verification, and RPC serving (docs/review/node-serving-review-20260915.md): crates/node/src/rpc_cli.rs beyond the accept-budget repair in 83488d91 and 15af691d, crates/node/src/transport_runtime.rs, crates/node/src/lifecycle_queries.rs, crates/node/src/node_types.rs, and the deployment-manifest verification path the systemd units run before start (the deployment-manifest-verify subcommand and what it calls). Live shadow and swap services (docs/review/shadow-swap-services-review-20260915.md): crates/node/src/cobalt_shadow.rs and crates/node/src/fastswap_service.rs, plus crates/node/src/batch_snapshot.rs only where these services use it. Node command tools and governance agent (docs/review/node-cli-governance-review-20260915.md): crates/node/src/bin/, crates/node/src/governance_agent_parts/, and crates/node/src/cli_dispatch.rs; crates/node/src/execution_actions.rs only for the command dispatch and interlocks (its state transitions were burn 3 surface A2).
