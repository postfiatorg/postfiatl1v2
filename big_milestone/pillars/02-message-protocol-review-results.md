# Pillar 2 message protocol review

**Decision, 27 November 2026 — hold production FastPay payouts and x402 settlement.** The strongest live evidence is nine accepted native consensus payments. The payout driver still needs a durable production lease and recovery implementation. The x402 adapter still needs native signing and independently authenticated committee certificates. The Mac can save a two-leg transfer at a stage that the UI cannot resume. These are independently actionable findings.

Reviewed the [milestone](02-message-protocol.md) against L1 main `76618dfae`, Train A `d3d79e220`, Task Node `c4a0101c`, Apple `00d2857`, and Explorer `99a3412`. L1 #316 landed during review at `111727276`. Reconciled the wire changes and repeated the cross-runtime tests at that revision. The numbered entries follow the 27 November review specification. Proposed fixes below are pull requests. Passing focused tests describes the reviewed branches. It does not constitute release sign-off.

## Findings in specification order

### 1. Chain identifier widths and identity — P0, partially repaired

Transaction IDs, FastPay order hashes, and certificate digests occupy 48 bytes. Request commitments, recipient key IDs and raw CID SHA-256 digests have separate 32-byte contracts. Updated the existing L1 width PR onto the baseline main. Its subsequent CI rebuild produced a lane-export ELF and verification key that differ from the committed identity, so the PR remains open. [CI comparison](https://github.com/postfiatorg/postfiatl1v2/actions/runs/46055339947/job/140696357242) The Task Node mirror now checks present settlement identifiers at encoding and decoding, validates lane-specific receipts, and uses the accepted consensus transaction ID after fallback. Removed a synthetic change-object ID derived by truncating an order hash. The adapter now validates node transaction IDs and returns the accepted native payment's ID. [L1 width fix #311](https://github.com/postfiatorg/postfiatl1v2/pull/311) · [Task Node #457](https://github.com/postfiatorg/tasknode/pull/457) · [L1 adapter #314](https://github.com/postfiatorg/postfiatl1v2/pull/314)

**Remaining failure:** the x402 client signs an application JSON representation. Its `computeFastPayOrderHash` and `computeConsensusTxHash` use that representation, and the MCP client compares the response against the result. A valid chain receipt can therefore fail the client's equality check. Changing the width cannot establish identity. Use the chain signer and signed transaction bytes end to end. Require client, facilitator, node and archive to agree on the same identifier for each lane while retaining the client's equality check. [Facilitator](../../tools/x402-facilitator/facilitator.js) · [MCP client](../../tools/x402-facilitator/mcp-client.js)

### 2. Payout leases, fallback and fee parity — P0, production recovery unproved

The driver saves the signed order before broadcast and reuses it when the outcome is unknown. Fallback requires a verified recovery decision and object rotation. The driver persists a fallback-unknown state before consensus submission. The repository supplies an in-memory payout store and an injectable driver. I found no production database implementation that atomically leases the object/version and durably records the signed order. Two workers and a fresh process after a lost RPC reply remain unverified. A store method returning success in a unit test cannot establish a database commit.

Fixed consensus fallback receipt identity, removed synthetic spendable change, and aligned JavaScript's zero inputs, empty weight, 511/512/513 byte boundaries and overflow behavior with Rust. Fourteen Task Node tests passed, including signing bytes and a Rust-generated FastPay vector. **Release requirement:** implement the unique payout and object/version constraints, transactional lease and order persistence, and a durable fallback attempt ID. Exercise two workers and restart after broadcast against that database. Require one observed chain payment for the payout. [Task Node #457](https://github.com/postfiatorg/tasknode/pull/457)

### 3. Train A fee activation, resource bounds, indexes and replay — P0, focused tests passed

- **Admission.** The owned-transfer fee implementation is in `crates/execution/src/owned_transfer.rs`. Ceiling division, unsigned net object growth and checked fee arithmetic match the published formula. The activation/cap test passed. Added empty counts, adjacent quantum boundaries, 2,048 input counts and overflow checks. These arithmetic cases do not represent a serialized maximum-size order. A full pre/post-activation historical replay across separate nodes is outstanding.
- **Object growth.** Global and per-owner caps constrain growth across splits and new owners. The proposed change counts existing objects for all growing owners in one traversal while preserving sorted error selection. Admission still scans existing objects when an owner grows. Measure worst-case block processing on a representative ledger before setting a throughput target.
- **Downgrade and upgrade.** The marker records height. Added a two-block fixture with an older marker and a missing order row. Reopening restores the height-two row. The second open performs zero scans, reads or writes in the backfill counters. The once-only, missing-marker and interrupted-commit tests also passed.
- **History.** The order index derives rows from confirmed recovery effects and uses the order digest. A node integration test covered sender/recipient queries and lookup by order hash. Full byte-equivalence across independent archives with transfer, unwrap, repeated recipients and pruned checkpoints remains unverified.
- **FastSwap and vaults.** The fresh-prepare path checks the fence. Certified catch-up uses a separate path. Two node-binary tests passed for a partially held lock and a later freeze. The multi-series trustline prune/bounded-clawback test passed. The full Train A execution library then reported 315 passed and two ignored. The node and storage tests used targeted fixtures.

[Train A #295](https://github.com/postfiatorg/postfiatl1v2/pull/295) · [Train A follow-up #317](https://github.com/postfiatorg/postfiatl1v2/pull/317)

### 4. x402 validator RPC, finality and replay — P0, production adapter blocked

The original mock accepted a different response shape from native node RPC. The patch checks the `postfiat-local-rpc-v1` envelope, request ID, `confirmed`, `receipt.accepted`, block-header height, and matching 48-byte IDs in the archived payment and receipt. It binds native payment chain, payer, payee, amount and signed request memo. It refuses unsupported issued-asset evidence. Fixture end-to-end, 25 refusal cases, and the adapter suite passed, including a combined checkout of #311, #314, #315 and merged #316. The combined checkout also passed 12 Python SDK cases, the JS protocol suite and the protoc round trip. [Adapter #314](https://github.com/postfiatorg/postfiatl1v2/pull/314) · [Node RPC inventory](../../docs/runbooks/rpc-method-inventory.json)

The built-in FastPay adapter counts returned RPC votes and constructs a certificate representation that differs from the node's signed-order and certificate types. Multiple URLs cannot authenticate committee membership. The patch prevents URLs alone from selecting this adapter in production. Bind votes to the order, chain, pinned registry and active epoch, verify distinct validator ML-DSA signatures with the native quorum rule, then verify application and indexed order identity. Test the actual RPC transport used by the deployment. [Original adapter #312](https://github.com/postfiatorg/postfiatl1v2/pull/312) · [Native verifier in Train A](https://github.com/postfiatorg/postfiatl1v2/blob/d3d79e220/crates/execution/src/owned_transfer_recovery.rs)

The facilitator caps HTTP bodies at 256 KiB and applies IP/key admission before signature work. Authenticated payer limits apply later. The spent-file tests exercise a shared local file and restart. Independently mounted replica files and ephemeral volumes do not provide one durable claim. Require a single transactional uniqueness boundary across all serving replicas and exercise concurrent settlement and a lost response before horizontal rollout. [Facilitator](../../tools/x402-facilitator/facilitator.js)

### 5. Cross-runtime cryptography and custody — P1, JS/Python interoperable

JS and Python each produced signed PUBLIC, PRIVATE and SEALED envelopes using real algorithms and public test keys. Both readers opened each producer's outputs and checked the expected chain and sender, for 12 checks. Both runtimes authenticated and reassembled both producers' encrypted three-chunk manifests. Three official X-Wing vectors agreed with JS and a Python reference reconstruction. These exercises cover the implemented signature, AAD, key derivation and wrapping preimages on the tested paths. Task Node now checks the signed header sender and passes the expected chain, transaction sender and CID through private decryption. After #316 landed, Task Node still emitted stable recipient IDs and could not open the new SEALED wraps. The Task Node patch now emits and reads blinded tags and content-key commitments. Each of the JS and Python SDKs opened Task Node PRIVATE and SEALED messages, and Task Node opened both producers’ messages in both modes. Its reward builder explicitly constructs the recipient list and can add the service key on the reward path. No global reader policy across unrelated clients was established. [X-Wing Appendix C](https://datatracker.ietf.org/doc/html/draft-connolly-cfrg-xwing-kem-11#appendix-C) · [Task Node #457](https://github.com/postfiatorg/tasknode/pull/457)

Seven Rust wallet signing tests and two Apple KDF tests passed, including the five shared golden vectors and Unicode passphrase normalization. The wallet exposes key derivation and public NFT envelope signing. I found no general Rust/WASM PRIVATE/SEALED/manifest reader and writer to complete the matrix. KDF intermediates use zeroizing buffers. The review did not establish zeroization for every caller, every CEK or every JS engine, or panic freedom for all untrusted inputs. Add the missing wallet API and run the same corpus through the compiled WASM boundary. [Wallet exports](../../crates/wallet_wasm/src/lib.rs) · [Wallet KDF](../../crates/wallet_wasm/src/unified_kdf.rs)

### 6. Explorer HTML, reward attribution and gateway bounds — P1, rendering tightened

The site used index-supplied verification metadata to award a trusted badge. The patch requires an operator-configured 1,952-byte ML-DSA-65 public key, matching signed-header and transaction sender accounts, reward schema, private visibility and the reported verification result. With no configured key, messages receive ordinary labels. Fragment attributes and abbreviated identifiers passed to HTML renderers are escaped. Six Explorer contract tests, browser-script syntax and the full Hugo build passed. [Explorer #64](https://github.com/postfiatorg/postfiatorg.github.io/pull/64)

The static site consumes indexed JSON. It cannot independently establish the index's raw signature, public-key-to-account derivation, or CID verification from a boolean. The upstream fetcher needs evidenced CIDv1 raw verification, a 1 MiB streaming limit, timeout, recursion/multipart budgets and denylist enforcement. Obtain the official payout key through the release configuration and test the actual index/browser pair before enabling trusted attribution. No shared-devnet browser sign-off was obtained.

### 7. Mac Make private, direct RPC and privacy — P1, resumability blocked

Rust persists job stages, signed unwrap material and identities. Five Make private tests passed, including a simulated restart, and three light-client tests passed for threshold and certified-root handling. The light client checks validator identity uniqueness. The Mac flow can separately accept a digest from one endpoint. The patch checks its exact lowercase 48-byte encoding. That check alone cannot authenticate a certificate. The hosted relay is explicitly selected in the reviewed transport. [Apple #42](https://github.com/postfiatorg/tasknode-apple/pull/42)

The Swift driver dispatches initial unwrap and proof generation. A fresh proof can be submitted on that path, but resuming a job whose next action is poll unwrap, submit saved shield, or poll shield receipt lacks equivalent dispatch. The UI can leave a funded job unfinished. Wire all saved actions to authenticated finality, reuse the persisted proof and check both legs on restart. Message history now distinguishes API/ledger observations from verified envelope signers. The Rust leak-capture harness passed. Capture with both Swift views active remains outstanding. [Swift flow](https://github.com/postfiatorg/tasknode-apple/blob/00d2857/mac/Sources/V2/PqPrivateView.swift) · [Rust flow](https://github.com/postfiatorg/tasknode-apple/blob/00d2857/core/src/make_private.rs)

### 8. Protobuf canonicality and unknown fields — P2, decoder fixes proposed

The SDK patches reject unknown v5 pointer fields and enforce canonical byte encoding for strict pointer decoding. The Task Node decoder checks its 256-byte pointer budget and rejects noncanonical representations. The two L1 SDKs reject unknown outer envelope, key-binding and top-level x402 fields. Unknown bytes inside signed headers retain their independent forward-compatibility rule. Task Node also rejects unknown outer envelope fields and caps raw decode at 1 MiB. Ten Python protocol tests and JS frozen-vector/real-PQ tests passed. The vector checker used real protoc to round-trip 10 vectors and checked 40 message and 18 enum declarations. Exhaustive malformed-input equivalence across every nested message and runtime remains unverified. [Wire fixes #315](https://github.com/postfiatorg/postfiatl1v2/pull/315) · [Task Node #457](https://github.com/postfiatorg/tasknode/pull/457)

### 9. SEALED metadata and directory rollback — P2, directory trust unresolved

SEALED writers omit the wrap's recipient account. Thread and reply fields default empty but can carry caller-supplied metadata. The SDK does not construct the funding transaction or enforce sender self-payment. Two self-payments are visible in the reviewed SEALED examples. Merged #316 added blinded SEALED tags, content-key commitments, signed key rotation and a verifier option for the minimum known epoch. The key-binding verifier checks the signed binding, key identity and signer association. An optional minimum supplied by the caller requires a trusted source that survives restart. [L1 #316](https://github.com/postfiatorg/postfiatl1v2/pull/316) I found no end-to-end client lookup that compares onboarding results with finalized on-chain identity and persists the highest verified epoch per chain/account. Add that state at the wallet directory boundary, including same-epoch conflicts, restart and legitimate key rotation. [JS protocol](../../wallet-proxy/message-protocol.js) · [Python protocol](../../python/postfiat_rpc/message_protocol.py)

### 10. IPFS outbox and relay — P2, first-pin durability unresolved

FastPay schedules the initial pin asynchronously. Failure can be swallowed, and a confirmed payout can return before scheduling another attempt. Task Node has a durable replication worker with backoff for existing pin jobs. The first reward-envelope pin still needs a unique durable job committed with the payout. General-purpose IPFS upload code permits a larger limit than the message contract. Verify authentication, rate limits, streamed 1 MiB enforcement and computed raw CID on the specific browser-facing message route. Test a fresh process after first-pin failure. [Payout driver](https://github.com/postfiatorg/tasknode/blob/c4a0101c/server/l1/fastpay-payout.js) · [IPFS integration](https://github.com/postfiatorg/tasknode/blob/c4a0101c/server/context-ipfs.js)

The relay write policy uses an allowlist and NIP-42 authentication. The inspected policy path does not execute a shell command. Fixed malformed JSON record types and invalid timestamps that could terminate its policy reader. Four relay tests passed. [Relay fix #315](https://github.com/postfiatorg/postfiatl1v2/pull/315)

### 11. Production secret-key providers — P2, deployment inventory required

Python accepts caller-supplied crypto callbacks. The reviewed reference tools and evidence use pure-Python implementations. No production call site using those packages was identified in the four reviewed trees. Dependency injection prevents these trees from establishing which providers every deployment supplies. Record the production entry points and providers for signing, decapsulation and decryption. Enforce the approved native implementation there, with a startup/test check that refuses the reference provider. Test vectors with public keys do not attest constant-time behavior. [Python SDK](../../python/postfiat_rpc/message_protocol.py) · [Wallet exports](../../crates/wallet_wasm/src/lib.rs)

### 12. Schema distribution and public claims — P2, CI fix proposed

The canonical and bundled proto trees matched, including message, NFT and governance schemas. CI previously lacked an exact check across both complete trees. Added a recursive byte comparison that also catches additions and deletions. Corrected the public write-up's Rust/WASM capability, FastPay performance and settlement claims. [Proto CI #313](https://github.com/postfiatorg/postfiatl1v2/pull/313) · [Publication corrections #64](https://github.com/postfiatorg/postfiatorg.github.io/pull/64)

Read the public block records at heights 1923–1931. All nine published transaction IDs matched accepted native payments. Decoding their signed payment memos reproduced the published pointer CIDs. Fees totalled 199 atoms (eight at 22 and one at 23). The separate block 1932 had one accepted native payment with a 48-byte transaction ID and a 22-atom fee. Archive evidence proves the on-chain memo commitment. It cannot establish current gateway availability, recipient decryption, FastPay latency or validator quorum. [Published evidence](https://postfiat.org/evidence/message-protocol/devnet2-live-verification-20261127.json) · [Block 1923](https://postfiat-explorer-api.fly.dev/api/explorer/v1/block/1923) · [Block 1932](https://postfiat-explorer-api.fly.dev/api/explorer/v1/block/1932)

## Pre-rollout decision by gate

| Gate | Status on 27 Nov | Evidence needed for sign-off |
| --- | --- | --- |
| G1, 48-byte identifiers | Open | Merge the L1 and Task Node fixes and exercise an MCP round trip in which the signed native transaction, receipt, client and index all report the same ID. |
| G2, Rust/JS/Python matrix | Partial | JS/Python and three-chunk cases passed. Supply Rust/WASM private and sealed APIs, then run every writer against every reader. |
| G3, live Train A settlement | Blocked | Deploy an approved Train A build, use native signed orders and authenticated active-committee votes, then reconcile applied certificate and indexed order from live validators. |
| G4, payout crash recovery | Blocked | Supply the production durable payout store. Kill the process after broadcast, restart separately, and reconcile one persisted order, one lease and one paid amount. |
| G5, Explorer trust and rendering | Local tests passed | Verify the trusted key and upstream index proof path. Capture a benign outsider-signed reward and inert text fixture rendering correctly in the deployed browser. The specified shared-devnet exercise has no sign-off here. |
| G6, Mac direct-RPC leak capture | Core test passed | Run the native app with both views active, exercise restart and both payment legs, and capture transport destinations and payload classes. The Linux core harness does not exercise SwiftUI. |

**Merge sequence.** Land the width and decoder changes together with their regenerated fixtures. Run the combined client/adapter tests. Land the Train A follow-up into its parent, then validate deterministic replay before rollout. Keep production payouts and x402 gated until G3 and G4 have durable evidence. Keep Mac recovery and Explorer attribution gated on their own release evidence.
